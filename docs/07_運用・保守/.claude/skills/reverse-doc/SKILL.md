# reverse-doc（docs/07_運用・保守、Zone3リバース生成）

> 版数: M4実装（実装対象: docs/v2/02_実行基盤アーキテクチャ.md 9章、
> docs/v2/04_運用設計体系定義書.md 5.2節・5.3節）

## 責務

`00-04_運用項目一覧.md`の分類コード（B1〜B6/I1〜I7/M1〜M10）ごとに、04文書5.3節が
定める**固定の対応表**（案件によらない）に従い、`07-00`（単独文書、全項目をセクションと
して格納）と`07-10`/`07-20`/`07-30`（群、分類項目ごとの固定文書）を生成する。

## 04文書5.3節の固定対応表（案件によらない、本実装はこれを再定義しない）

分類コードと07番文書の対応は`.claude/lib/ops-mapping.js`に集約する（`00-04`が
07番への生成先リンク列を持たない理由と同じ設計判断、04文書3.2節）。

## 6章: リバース生成の可否と、前に置くべきもの（04文書6章）

条件B該当項目（M2インシデント管理、B5ユーザー側運用業務、M10システム廃止方針等）は
判断基準・体制情報を実物から復元できないため、対応する決定ログ（`運用項目コード`
frontmatterフィールド）が無い場合は「未記載」と明記する（実装から推測しない、MUST）。
