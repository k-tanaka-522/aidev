# AI開発ファシリテーター 設計書

## 1. 概要

### 1.1 設計の目的
要件定義で定義した機能を、Claude Code の `.claude` ディレクトリを活用して実装する。
エンジニア・非エンジニアを問わず、自然な対話でシステム開発プロセス全体をファシリテートするAIアシスタントを構築する。

### 1.2 設計方針
1. **Claude Code準拠**
   - `.claude` ディレクトリの標準構造に従う
   - CLAUDE.md をエントリーポイントとする
   - カスタムコマンドとエージェントを活用

2. **段階的実装**
   - Phase 1: ローカル完結（`.claude` 設定のみ）
   - Phase 2以降: MCP連携（将来拡張）

3. **実用主義**
   - まず作って使って調整
   - 完璧を目指さず、実用性を優先
   - フィードバックで改善

### 1.3 技術スタック
- **Claude Code** - ベースプラットフォーム
- **Markdown** - ドキュメント形式
- **JSON** - 状態管理
- **Git** - バージョン管理
- **Mermaid** - 図の生成

### 1.4 Claude Code 設計原則

#### コンテキスト最適化
大規模プロジェクトでのコンテキスト消費を最小化するため、以下の戦略を採用：

| 機能 | 戦略 | 効果 |
|------|------|------|
| **Skills** | description のみ起動時読み込み、内容はオンデマンド | 40-50%削減 |
| **Rules** | `paths:` frontmatter による条件付きロード | 30-40%削減 |
| **Subagent** | 独立コンテキスト + 必要tool限定 | 25-35%削減 |

#### セッション永続化
セッション切断後も継続できるよう、`.claude-state/` に状態を永続化：
- `progress.md`: 進捗状況、次のアクション
- `decisions.json`: 意思決定レコード
- `reviews/`: レビュー記録

#### 層分離の強制
Hooks と Permissions で PM 層違反を技術的に防止：
- **PreToolUse Hook**: PM が src/, infra/, tests/ を直接編集しようとしたらブロック
- **Permissions**: 読み書き権限をエージェントごとに制限

## 2. システムアーキテクチャ

### 2.1 全体構成

```mermaid
graph TB
    User[ユーザー] -->|自然言語で対話| PM[PM エージェント]
    PM -->|委譲| SubAgents[サブエージェント群]

    subgraph SubAgents[サブエージェント]
        AppArch[App-Architect]
        InfraArch[Infra-Architect]
        Coder[Coder]
        QA[QA]
        SRE[SRE]
        Designer[Designer]
        Consultant[Consultant]
    end

    PM -->|読み込み| CLAUDE_MD[CLAUDE.md]
    SubAgents -->|読み込み| Docs[.claude/docs/]
    SubAgents -->|参照/更新| State[.claude-state/]
    SubAgents -->|生成| ProjectDocs[docs/]
    SubAgents -->|生成| Code[src/, infra/, tests/]
```

### 2.2 エージェント層構成（3層モデル）

```
Layer 1: PM（オーケストレーション層）
  - ユーザー対話
  - タスク委譲
  - 進捗管理
  - 品質ゲート管理
  ↓
Layer 2: サブエージェント（専門家層）
  - App-Architect: アプリケーション設計
  - Infra-Architect: インフラ設計
  - Coder: コード実装
  - QA: テスト
  - SRE: インフラ実装・運用
  - Designer: UI/UXデザイン
  - Consultant: ビジネス助言
  ↓
Layer 3: 成果物
  - docs/: 設計書
  - src/: アプリケーションコード
  - infra/: IaCコード
  - tests/: テストコード
```

### 2.5 Rules 設計

Rules は `paths:` frontmatter で条件付きロードする。不要なルールのロードを防ぎ、コンテキストを最適化。

```
.claude/rules/
├── 00_common.md                    # 全体共通（paths なし）
├── 10_requirements.md              # paths: docs/02_要件定義/**
├── 20_app-design.md                # paths: docs/03_アプリ/**
├── 30_infra-design.md              # paths: docs/04_インフラ/**
├── 40_typescript.md                # paths: src/**/*.{ts,tsx}
├── 50_terraform.md                 # paths: infra/**/*.tf
└── 60_testing.md                   # paths: tests/**
```

### 2.6 Hooks 設計

```json
{
  "hooks": {
    "SessionStart": [
      {
        "command": ".claude/hooks/restore-session-context.sh"
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "command": ".claude/hooks/prevent-pm-layer-violation.sh"
          }
        ]
      }
    ]
  }
}
```

**restore-session-context.sh**:
```bash
#!/bin/bash
if [ -f ".claude-state/progress.md" ]; then
  PHASE=$(grep "^## 現在のフェーズ" .claude-state/progress.md | head -1)
  echo "📊 前回進捗: $PHASE"
fi
```

**prevent-pm-layer-violation.sh**:
```bash
#!/bin/bash
file_path="$2"
if [[ "$file_path" =~ ^src/|^infra/|^tests/ ]]; then
  echo "⚠️ PM層違反: $file_path"
  exit 2  # ブロック
fi
exit 0
```

### 3.2 PMエージェント（CLAUDE.md）

#### 役割
- **オーケストレーション専任**: 成果物を作成しない
- ユーザーとの対話（一問一答、ビジネス背景優先）
- サブエージェントへの委譲（Task ツール使用）
- TodoWrite でタスク追跡
- 品質ゲート管理（レビュー）

#### 禁止事項
- docs/, src/, infra/, tests/ の成果物作成
- 技術標準を自分で読んで判断

#### 委譲ルール
```
ユーザー要望 → PM: 専門的内容か判断 → YES
  ↓
Task ツールでサブエージェントに委譲
  ↓
サブエージェント: 成果物作成
  ↓
PM: レビュー（チェックリスト使用）
  ↓
PM → ユーザー: 成果物を提示
```

### 3.3 App-Architect エージェント

#### 役割
- アプリケーション設計書の作成
- Coderへの実装指示

#### 出力先

docs/03_アプリケーション設計/
├── 01_基本設計/

#### 必須セクション: 06_実装方針.md
- ディレクトリ構成（src/ 配下の詳細）
- エントリーポイントファイル名
- 環境変数一覧
- ポート番号
- 推定行数と分割理由

### 3.5 Coder エージェント

#### 役割
- アプリケーションコードの実装
- 設計書（06_実装方針.md）に従った実装

#### 出力先
- src/: 本番コード
- prototypes/: プロトタイプ

#### 必須チェック（実装前）
1. 設計書の存在確認
2. 既存ディレクトリ構成の確認（二重実装防止）
3. 環境変数・ポート番号の確認
4. インフラ設計との整合性確認

- **SRE**: IaC実装、デプロイ、運用

## 7. 成果物構成の整合性管理

### 7.1 正のドキュメント

**`.claude/docs/10_facilitation/0.1_成果物構成設計.md`** を成果物構成の「正」とする。

### 7.2 整合性ルール

1. エージェント定義（AGENT.md）の出力先 = 成果物構成設計の構成
2. テンプレートファイル = 成果物構成設計の構成に準拠
3. 矛盾が発生したら、成果物構成設計を正とする

### 7.3 修正時のチェックリスト

- [ ] 成果物構成設計と一致しているか
- [ ] 出力先パスが正確か
- [ ] ファイル名が一致しているか
- [ ] エージェント責務が明確か

## 9. 成功基準

### 9.1 フレームワークの成功基準

1. **エージェント連携**
   - PM → サブエージェントの委譲が正しく動作
   - クロスレビューが機能
   - 成果物の出力先が一貫

2. **成果物品質**
   - 設計書が実装可能なレベル
   - コードが設計書に準拠
   - テストがカバレッジ基準を満たす

3. **整合性**
   - app/infra 分離が維持
   - ポート番号等の不整合なし
   - 二重実装なし

## 10. 継続開発対応設計

> 詳細は [ユーザーストーリー](./05_ユーザーストーリー.md) の「継続開発」セクションを参照

### 10.1 変更規模判定

| レベル | 内容 | aiDev の対応 |
|--------|------|-------------|
| **Patch** | バグ修正 | 影響確認 → 修正 → テスト |
| **Minor** | 機能追加・改善 | 設計書更新 → 実装 |
| **Major** | 要件レベルの変更 | 要件定義から見直し |

### 10.2 継続開発フロー

```mermaid
flowchart TD
    A[変更要望] --> B{変更規模判定}
    B -->|Patch| C[影響確認]
    B -->|Minor| D[設計書更新]
    B -->|Major| E[要件定義見直し]
    C --> F[修正実装]
    D --> F
    E --> D
    F --> G[テスト]
    G --> H[デプロイ]
```

### 10.3 整合性維持

- 設計書とコードの一貫性を保つ
- 変更時は関連ドキュメントを更新
- `.claude-state/decisions.json` に変更理由を記録

### 10.4 プロジェクトスナップショット

継続開発時、各エージェントが既存の設計・コードを理解するための共通インデックス。

#### スナップショット構成

```
.claude-state/snapshot/
├── architecture.md      # アーキテクチャ概要（50-100行）
├── codebase.md          # コード構造サマリー
├── dependencies.md      # 依存関係・技術スタック
└── last-updated         # 最終更新タイムスタンプ
```

#### スナップショット内容

| ファイル | 内容 | 更新トリガー |
|---------|------|-------------|
| `architecture.md` | 設計書の要約、主要コンポーネント、データフロー | docs/ 更新時 |
| `codebase.md` | ディレクトリ構造、主要ファイル一覧、エントリーポイント | src/, infra/ 更新時 |
| `dependencies.md` | package.json, requirements.txt 等の依存関係 | 依存ファイル更新時 |

#### 利用方法

1. **エージェント起動時**: `snapshot/` を読み込み、プロジェクト全体像を把握
2. **詳細確認時**: snapshot に記載の `@参照` から該当ファイルを読み込み
3. **変更検知時**: Hook が自動で snapshot を更新

#### Hook 設定（PostToolUse）

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/update-snapshot.sh"
          }
        ]
      }
    ]
  }
}
```

#### エージェント共通指示

全サブエージェントの AGENT.md に以下を追加：

```markdown
## セッション開始時

1. `.claude-state/snapshot/` を読み込み、プロジェクト構造を把握
2. 必要に応じて @ 参照先を詳細確認
3. 既存の設計・実装との整合性を意識して作業
```
