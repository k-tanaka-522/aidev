# review（docs/02_要件定義、Zone3レビュー）

> 版数: M4実装（実装対象: docs/v2/02_実行基盤アーキテクチャ.md 11章、9.3節）

## 責務

`reverse-doc`が生成した要件定義書一式について、`context: fork`の独立コンテキストで
以下を検証する。

1. **完全性**: 03文書3.4節の必須区分（4章の判断基準を適用した結果）に対応する文書が
   すべて生成されているか（`00-01`カタログの該当行が「生成済み」になっているか）
2. **決定ログとの整合**: 「2.5 決定ログからの引用」節が実在する決定ログを参照しているか
   （でっち上げ・実装からの推測で埋めていないか、02文書9.3節・8.6節）
3. **逆差分の有無**: `HB-ID`全件が`00-02`台帳に存在し、対応するシナリオが実装（`tests/e2e/`）
   に存在するか（9.3節の逆差分検出。ただし逆差分の主要な機械判定は`traceability-reverse`
   （05番）が担うため、本レビューは02番固有の観点として「機能要件一覧が実際のHB-ID台帳と
   1件も欠落なく対応しているか」の目視確認に限定する）
4. **`requirements-first`選択時のみ**: `02-99`差分検査レポートの判定が正しく`00-14`へCRとして
   起票されているか

## ツール権限
