# Status Command（v2: ゾーン/レーン状況の確認）

このコマンドは、プロジェクトの現在のゾーン・レーン進捗・ゲート状況を分析し、ユーザーに提示する。

セッションをまたいでプロジェクトを継続する際に有用である。

---

## 実行方法

```
/status
```

---

## このコマンドがすること

あなた（Claude）は、以下のファイルを**読み取り専用で**確認し、状況を整理する。
**新たなゲート判定（`gate-check` の実行）は行わない**（後述「してはいけないこと」参照）。

### 1. ゾーン状態

- `.claude-state/current-zone.json` — `zone`（`0`/`1`/`3`/`4`のいずれか。**`2`という値は存在しない**、
  `docs/v2/02_実行基盤アーキテクチャ.md` 10.2.1節）、`src_unlocked`（app-architect/coderの
  `src/**`書込許可）、`zone3_freeze_tag`（Zone3のas-built生成基準点）、`zone3_hotfix_active`
  （Zone3内ミニチケット処理中か）。**ファイルが存在しない場合は「Zone 0 未着手」の既定値として扱う**
  （エラーにしない）
- `.claude-state/process-option.json` — プロセス・オプション（標準`prototype-driven`/例外
  `requirements-first`）。存在しなければZone0でまだ選択されていない

### 2. 決定ログとゲート

- `docs/00_プロジェクト管理・ガバナンス/decisions/` 配下の `DL-*.md`（決定ログ）。うち
  `DL-0000_process-option.md` はプロセス・オプション選択の正本
- `.claude-state/decision-warnings.json` — 決定ログの書き忘れ警告の未解消件数
- `.claude-state/zone-gate-retry.json` — `GZ0`/`GZ2`/`GZ3`各ゲートの
  `{retryCount, hold, heldAt}`。ファイルが存在しなければ全ゲート未判定（0回、HOLDなし）として扱う
- `docs/00_プロジェクト管理・ガバナンス/GZ0-99_ゲート記録.md`・`GZ2-99_ゲート記録.md`・
  `GZ3-99_ゲート記録.md` — 各ゲートの直近判定結果（GO/NG/HOLD/RESET）。ファイルは該当ゲートが
  一度も判定されていなければ存在しない（異常ではない）
- Zone0のとき、決定ログの9カテゴリ充足状況をより正確に把握するため、`decision-check` Skill
  （`Read`/`Grep`/`Glob`/`Bash`のみで実装された読み取り専用スクリプト、副作用なし）を
  呼び出してよい（推奨）。手動での目視集計より正確である

### 3. レーン進捗（Zone1・Zone2、機能単位で重なる）

- `docs/00_プロジェクト管理・ガバナンス/00-02_HBトレーサビリティ台帳.md`（`HB-ID`、経由する
  `SCR-ID`/`RPT-ID`/`API-ID`）
- `docs/00_プロジェクト管理・ガバナンス/00-03_バッチトレーサビリティ台帳.md`（`BAT-ID`）
- `docs/00_プロジェクト管理・ガバナンス/00-04_運用項目一覧.md`
- `docs/00_プロジェクト管理・ガバナンス/00-05_同期点記録台帳.md`（ミニゲート＝レーン間同期点の
  通過実績。最新エントリの通過日時・参加レーンを確認する）
- `prototypes/SCREEN_ID_INDEX.md`・`prototypes/REPORT_ID_INDEX.md`（レーンAの画面/帳票ハリボテ
  採番状況）
- Zone3以降: `.claude-state/zone3-hotfix-count.json`（Zone3内ミニチケットの差し戻し。ゾーンゲート
  側`zone-gate-retry.json`とは独立したカウンタ）
- Zone4: `.claude-state/mode-b-ticket-retry.json`（Mode Bチケットの差し戻し）

### 4. 課題・リスク・変更管理

- `docs/00_プロジェクト管理・ガバナンス/00-12_リスク管理台帳.md`
- `docs/00_プロジェクト管理・ガバナンス/00-13_課題管理表.md`
- `docs/00_プロジェクト管理・ガバナンス/00-14_変更管理台帳.md`
- いずれも、対応する事象（リスク・課題・変更要求）が一度も発生していなければファイル自体が
  存在しないことがある（異常ではない。台帳は各Skillが必要時に作成する）

### 5. IPA標準成果物（Zone3以降）

- `docs/02_要件定義/`〜`docs/07_運用・保守/` — **Zone3到達前はディレクトリ直下が空であることが
  正常**（`docs/v2/02_実行基盤アーキテクチャ.md` 4.2.1節）。例外は `06_移行・導入`（Zone3〜4境界
  まで生成されない）と、プロセス・オプションが`requirements-first`の場合の`02_要件定義/`
  （Zone1のうちから前倒しで生成されうる、8.7節）
- `docs/00_プロジェクト管理・ガバナンス/00-01_成果物構成カタログ.md` — Zone3のリバース生成先
  カタログ（生成済みマーク欄を持つ）。**現時点のリポジトリにはこのファイルが存在しない
  （既知の欠落。詳細は本コマンド末尾の注意を参照）**

### してはいけないこと（MUST NOT）

- **`gate-check` を実行しないこと。** ゲート判定を実行すると `GZ{0,2,3}-99_ゲート記録.md` への
  追記、および `zone-gate-retry.json` の差し戻しカウンタ更新という**副作用**を伴う
  （`docs/v2/02_実行基盤アーキテクチャ.md` 10.2.2節）。状況確認だけの目的で呼び出すと、
  実際には判定していないのに差し戻し回数が加算される事故になりうる。既存の記録ファイルを
  読むにとどめる
- `.claude-state/current-zone.json` 等の状態ファイルを自分で書き換えないこと（読み取りのみ）
- `src/`・`infra/`・`tests/` の中身を詳細に読みに行かないこと（PMの読み書き権限方針を維持する。
  実装の進捗はQA/Coderへの確認、または台帳ファイルの記載から把握する）

## 出力形式

現在のゾーンに応じて、以下の形式でユーザーに提示する。

```
📊 プロジェクト状況

【現在のゾーン】
Zone {0|1|3|4}: {ゾーン名}
プロセス・オプション: {prototype-driven（標準） | requirements-first（前倒し例外） | 未選択}

【Zone 0: 決定ログ】
✅ 充足カテゴリ: {n}/9
⏳ 未充足カテゴリ: [...]

【Zone 1: レーン進捗】（該当する場合）
🔄 レーンA（ハリボテ）: SCR-ID {n}件、RPT-ID {n}件
🔄 レーンB（契約モック・決定ログ）: ...
🔄 レーンC（インフラ決定）: ...
✅ 直近の同期点: {日時}（{参加レーン}）
src_unlocked: {true|false}

【ゲート状況】
✅/⚠️/🔴 GZ0: {未判定 | GO(日時) | NG(理由) | HOLD}
✅/⚠️/🔴 GZ2: {同上}
✅/⚠️/🔴 GZ3: {同上}

【課題・ブロッカー】
⚠️ 未解消の決定ログ警告: {n}件
⚠️ HOLD中のゲート: {あれば列挙}
⚠️ 00-13課題管理表のオープン項目: {n}件

【次にやるべきこと】
1. [アクション1]
2. [アクション2]
3. [アクション3]

どれから進めますか？（`/next` で最優先の1件のみを確認することもできます）
```

---

## 状態ファイルが存在しない場合

`.claude-state/current-zone.json` が存在しない場合、それ自体はエラーではなく「Zone 0 未着手」を
意味する。

```
このプロジェクトはまだ Zone 0（不可逆決定）に着手していません。

新しいプロジェクトを始める場合は `/init` を実行してください。
「〇〇を作りたい」と伝えていただければ、Zone 0 のヒアリングから始めます。
```

## 注意事項

### 状況の正確な把握

- 状態ファイルの情報を正確に読み取る。矛盾があればユーザーに確認する
- ゲート記録（`GZ{0,2,3}-99_ゲート記録.md`）と `zone-gate-retry.json` の内容が矛盾する場合
  （例: 記録上はGO済みだがretryStateにHOLDが残っている等）、断定せず「要確認」として提示する

### 既知の欠落（報告事項）

- `docs/00_プロジェクト管理・ガバナンス/00-01_成果物構成カタログ.md` は
  `docs/v2/02_実行基盤アーキテクチャ.md` 4.3節・9.4.3節・14.1節が「プロジェクト非依存の
  正本として継続する」と定めているが、移行元とされた v1 の
  `.claude/docs/10_facilitation/0.1_成果物構成設計.md` は M6 で削除済みであり、
  移行先の `00-01_成果物構成カタログ.md` 自体もこのリポジトリには存在しない。
  `gate-check` の `GZ2`/`GZ3` 判定条件はこのファイルの読み取りを前提としており、
  読めない場合は判定不能として **fail closed（NG）** になる（`.claude/skills/gate-check/SKILL.md`）。
  Zone3に到達する前にこのファイルの用意（テンプレートとしての新規作成、または移行）が
  必要になる可能性が高い。本コマンドはこの状態を検出したら必ずユーザーに知らせること

### 他のコマンドとの連携

- `/init` - プロジェクトの初期化・再開準備
- `/next` - 最優先の次の1アクションだけを簡潔に確認したい場合
