# Next Command（v2: 次の1アクション）

このコマンドは、次にやるべきことを1つだけ簡潔に表示する。

`/status` の簡易版で、状況の詳細ではなく「次のアクション」だけを知りたい時に使用する。

---

## 実行方法

```
/next
```

---

## このコマンドがすること

`/status` と同じ読み取り対象（ゾーン状態・決定ログ・ゲート記録・台帳）のうち、**次の1アクションを
決めるために必要な範囲だけ**を確認し、最も優先度の高いアクションを1つ提示する。
`/status` 同様、**`gate-check` は実行しない**（副作用を伴うため。既存の記録ファイルのみを読む）。

### 判定の優先順位

1. **いずれかのゲートがHOLD中か**（`.claude-state/zone-gate-retry.json` の該当ゲートが
   `hold: true`）→ 最優先。「ユーザーに事業判断を仰ぎ、HOLD解除の決定ログを起票する」手順
   （`docs/v2/02_実行基盤アーキテクチャ.md` 10.2.2節）を提案する
2. **直近のゾーンゲート判定がNGのまま再判定を待っているか**（`GZ{0,2,3}-99_ゲート記録.md` の
   最新エントリが`NG`）→ その「備考」欄・判定条件の不足から、差し戻し先（同一ゾーンのExecute、
   または前ゾーンへの戻り）を特定して提案する
3. **Zone 0 で決定ログの9カテゴリが未充足か**（`decision-check` Skillの読み取り専用集計、または
   決定ログの目視確認）→ 未充足カテゴリのうち1つを選び、ヒアリング（`decide` Skill、`zone0`）を
   提案する
4. **Zone 1 でレーン間の同期点（ミニゲート）が保留になっているか**（`00-05_同期点記録台帳.md`の
   最終通過から間が空いている、または特定レーンの成果物が他レーンと未突合）→ 次の同期点実施を提案する
5. **Zone 3 でリバース未生成の文書区分があるか**（`00-01_成果物構成カタログ.md`の生成済みマーク欄。
   このファイル自体が存在しない場合はその旨を最優先で報告する。「既知の欠落」として
   `.claude/commands/status.md` に記載のとおり）→ 次に生成すべき区分を提案する
6. 上記のいずれにも該当しない場合、現在のゾーン・レーンで最も次に進めやすい活動
   （例: Zone1でまだ着手していないレーンのハリボテ着手、Zone4で未処理のチケット等）を提案する

---

## 出力形式

```
🎯 次にやるべきこと

[具体的なアクション]

理由：[なぜこれが優先なのか、上記の判定の優先順位のどれに該当するか]

進めますか？
```

---

## 実装例

```
🎯 次にやるべきこと

Zone 0 の決定ログのうち「非機能骨格」カテゴリが未記録です。想定規模・可用性クラス・
データ主権の方針をヒアリングし、decide Skill で起票してください。

理由：GZ0（Zone0→Zone1のゲート）は決定ログ9カテゴリすべての充足を条件とします。
　　　現時点で8/9カテゴリが埋まっており、これが唯一の未充足項目です。

進めますか？
```

---

## 注意事項

- **1つだけ**提案する（複数は提案しない）
- **最優先のもの**を選ぶ（上記「判定の優先順位」に従う）
- **具体的**に記述する（どのSkill・どの決定を指すか明示する）
- **理由**を明確に説明する
- **新たなゲート判定・状態の書き換えは行わない**（`/status` と同じ制約）

## 他のコマンドとの連携

- `/status` - 状況の詳細（ゾーン・レーン・ゲート・課題）を確認したい場合
- `/init` - プロジェクトの初期化・再開準備
