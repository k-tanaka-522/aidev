# mockup-update（ハリボテ改修・軽量影響分析）

> 版数: M2実装（実装対象: docs/v2/02_実行基盤アーキテクチャ.md 5.2節。
> 01文書4.4.5節手順7「ハリボテが書き換わった場合の追随ルール」の機械支援）

## 責務

既存ハリボテの改修に伴う`SCR-ID`・入力項目の変化を検知し、その`SCR-ID`を経路に含む
`HB-ID`を`00-02`台帳から逆引きして特定した上で、影響を受けるレーンB（契約モック・
データモデル）・E2Eシナリオへの波及を警告する。

## 手順（MUST）

```
1. ウォームアップ: 対象HTMLをReadする
2. HTMLを改修（ユーザーとの対話に基づく）
3. node prototypes/.claude/skills/mockup-update/scripts/analyze-impact.js \
     --file=<改修したファイルの相対パス>
   を実行し、変化の種類（項目のみ／画面遷移構造）と影響候補（HB-ID、tests/e2e配下、
   src配下）を取得する
4. 01文書4.4.5節手順7の3区分に従い、ID追随を判断する（MUST）:
   - 画面単体の変更（項目の追加・削除、文言変更）: 既存のSCR-IDを維持し、
     SCREEN_ID_INDEX.mdの当該行を改訂する
   - 画面遷移の軽微な変更（経路上のSCR-IDの並びが変わらない範囲）: 既存のHB-IDを維持し、
     シナリオを改訂として扱う
   - 画面遷移の構造自体が変わる大幅な作り直し: 新しいHB-IDを採番し（sync-check経由）、
     旧IDは「統合済み」「廃止」として明示的にクローズする（MUST NOT黙って再利用）
5. 影響を受けるレーンB（契約モック・データモデル）・レーンC・QA（E2E改訂）へ連携する
```

## 入力・出力

- 入力: 変更依頼、既存HTML、`.claude-state/mockup-snapshots/{screen}.json`（直近のスナップショット）
- 出力: 更新後HTML、`SCR-ID`変更差分レポート（`analyze-impact.js`のJSON出力）、
  影響`HB-ID`一覧

## 軽量影響分析の限界（MUST把握）

- `tests/e2e/`・`src/`側の影響候補抽出は文字列一致（`SCR-ID`/`HB-ID`がファイル内容に
  含まれるか）による近似であり、意味的な追跡ではない（02文書10.3節が明記する機械抽出の
  限界と同種）
- HB-ID再採番の要否そのものは機械判定せず、QA/Designerの判断に委ねる（MUST NOT自動判定）

## 動作確認（M2）

- 項目のみの変更（フィールド追加）を検知し、既存SCR-ID維持の推奨が出ることを確認済み
- 画面遷移（リンク先）の変更を検知し、HB-ID再採番の判断を促す推奨が出ることを確認済み
- 00-02台帳からのHB-ID逆引きを確認済み
- tests/e2e・src配下の影響候補grepを確認済み

詳細な確認手順・結果はPMへの報告（本タスクの最終回答）を参照。
